# Обработка ошибок

## Подход

Ошибка — это фича, а не баг. Ошибка не пробрасывается автоматически: результат с ошибкой разбирается в месте вызова.

## Ошибка — значение

Ошибка — обычное значение. Что именно — решает программист:

```text
enum FileError {
    NotFound,
    PermissionDenied,
}
```

## Вычисление может вернуть «значение или ошибку»

```text
fn read_file() -> Data or FileError {
    ...
}
```

`T or E` — ответ вычисления. Это не разрешение пробрасывать ошибку: вызывающий обязан сразу разобрать результат.

## Обработка на месте

```text
sub main() {
    let result = read_file()
    switch result {
        FileError::NotFound => std.print("файл не найден"),
        FileError::PermissionDenied => std.print("нет доступа"),
        else => std.print(result),
    }
}
```

Если вычисление вызывает другое вычисление с `T or E`, оно тоже обязано обработать результат через `switch`. Голый вызов такого вычисления — ошибка.

## `?` нет

Оператора `?` в языке нет. Он выносит ошибку из места, где она возникла, — язык так не делает.

## Действие и ошибки

`sub` не возвращает ошибку. Если внутри действия вызывается вычисление с `T or E`, действие обязано обработать результат через `switch` внутри себя. Если действие не может этого сделать — это ошибка дизайна кода, а не повод возвращать ошибку наружу.

## Ленивый и подробный режимы

**Ленивый режим:** компилятор сам генерирует номер ошибки из места (файл, строка, вычисление или действие), номер ищешь в доках.

**Подробный режим:** сам пишешь, что положить в ошибку.

## `defer` — отложенное выполнение

`defer` — отложенное выполнение (закрытие ресурсов и т.п.):

```text
sub work() {
    let f = open(path)
    defer f.close()
    ...
}
```
