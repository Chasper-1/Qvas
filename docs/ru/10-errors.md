# Обработка ошибок

## Подход

Ошибка — это фича, а не баг.

## Модель как в Rust

- Функция возвращает «значение или ошибку»: `-> T or E` (аналог `Result<T, E>`).
- Ошибка — значение любого типа (имя, число, строка, структура, enum).
- Проброс ошибки — оператор `?` (как в Rust).
- Обработка — `switch` по вариантам ошибки (как `match` в Rust).

## Ошибка — значение

Ошибка — обычное значение. Что именно — решает программист:

```text
enum FileError {
    NotFound,
    PermissionDenied,
}
```

## Возврат «значение или ошибка»

```text
fn read_file() -> Data or FileError {
    ...
}
```

## `?` — проброс ошибки одной командой

```text
fn read_file() -> Data or FileError {
    let data = open(path)?    // проброс ошибки одной командой
    data
}
```

`?` пробрасывает ошибку наверх одной командой.

## Обработка ошибки

```text
fn.nothing main() {
    let result = read_file()
    switch result {
        FileError::NotFound => print("файл не найден"),
        FileError::PermissionDenied => print("нет доступа"),
        else => print(result),
    }
}
```

## Ленивый и подробный режимы

**Ленивый режим:** компилятор сам генерирует номер ошибки из места (файл, строка, функция), номер ищешь в доках.

**Подробный режим:** сам пишешь, что положить в ошибку.

## `defer` — отложенное выполнение

`defer` — отложенное выполнение (закрытие ресурсов и т.п.):

```text
fn.nothing work() {
    let f = open(path)
    defer f.close()
    ...
}
```
