# Типы

## Статические, 100%

Типы статические, 100%.

## Числовые типы

Целые со знаком: `i8`, `i16`, `i32`, `i64`.

Целые без знака: `u8`, `u16`, `u32`, `u64`.

Вещественные: `f32`, `f64`.

`bool`, `char`, `str` — отдельные базовые типы.

Литералы без контекста: целые — `i32`, вещественные — `f64`.

## Метки типов

`i32:id` — это `i32` с меткой `id`. Не новый тип: объявления нет, представление и операции те же. Метка проверяется статически и стирается в рантайме.

Это не newtype. `type Id = i32` — алиас, не новый тип. `struct Id(i32)` — новый тип. `i32:id` — ни то, ни другое: тип остаётся `i32`, метка видна прямо на типе.

Создаётся значением:

```text
let user_id: i32:id = 42
```

Теперь 42 — это `i32:id`. 42 не перестаёт быть `i32` — все операции `i32` работают. Но у значения есть метка `id`.

Вычисление или действие запрашивает тип с меткой:

```text
fn get_user(i32:id user_id) -> User { ... }
```

### Где проверяется

На границах: передача, возврат, поле, присваивание. Метка должна совпадать. Внутри выражения значение ведёт себя как `i32`, но на границе метка проверяется.

| Ситуация | Можно |
|---|---|
| `i32:id` → `i32:id` | да |
| `i32:id` → `i32` | нет: именованный тип туда, где его не ждут |
| `i32` → `i32:id` | нет: метки нет |
| `i32:id` → `i32:userId` | нет: метки разные |
| литерал `42` → `i32:id` | да: литерал принимает ожидаемую метку |

### Арифметика

Простой `i32` — нейтральный операнд. Метка сохраняется.

| Выражение | Результат |
|---|---|
| `i32:id + i32` | `i32:id` |
| `i32 + i32:id` | `i32:id` |
| `i32:id + i32:id` | `i32:id` |
| `i32:id + i32:userId` | ошибка |
| `i32 + i32` | `i32` |

То же для `-`, `*`, `/`, `%`.

### Сравнения

Метки не участвуют. Сравниваются значения, не типы.

```text
i32:id == i32          // bool
i32:id < 100           // bool
i32:id == i32:userId   // bool
```

## Источники: `i32:=id`

`i32:=id` — не тип и не метка. Это привязка к источнику: принимается `i32` от переменной `id`. «Кто говорит» закреплён: другой источник не подойдёт.

Используется только в месте приёма:

```text
sub print(i32:=data) { ... }
```

Внутри данные доступны по имени `data`. `i32:=data` нельзя использовать в `let`, `return`, как поле структуры, в арифметике или сравнении.

Вызов функции как источник (`i32:=f()`) не входит в v1: сигнатура функции уже задаёт тип, а внешние данные приходят через переменную.

## Единицы измерения

Единицы измерения — просто метка: `i32:meters`. Никакой специальной арифметики единиц нет (метры², метры/секунды не вычисляются). Объявил `i32:meters` — и передавай, куда нужно. Контракт — метка.

## Диапазоны — не в типы

Проверка диапазона — тупое сравнение, легко пишется явно:

```text
if x > 100 { ... }
```

Метка типа скрывала бы действие и делала его менее понятным, к тому же допускала бы выполнение действия разными способами. Если нужно — явная возможность писать о диапазоне (переменная, сигнатура вычисления или действия), а не метка типа.

## Принцип

> В типы идёт только то, что нельзя проверить обычным кодом.

`i32:id` — семантическая метка значения, обычным кодом не проверяется → обязательна. `i32:=id` — привязка к источнику, тоже не проверяется обычным кодом → обязательна. Диапазоны — проверяются обычным кодом (`if x > 100`) → не в типы.
