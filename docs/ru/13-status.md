## Что решено по блокам

- **Типы** — статические, 100%. Базовые типы: все типы.
- **Структуры** — способ собрать несколько разных значений в одно, обращение по имени поля.
- **Списки и массивы** — создаются и индексируются как везде.
- **`mut` + операторы** — `mut` и move не смешиваются: `mut` меняет значение, move меняет имя, ответственное за данные. Либо одно, либо другое.
- **Инвалидация вложенных ссылок** — по пути: мутация убивает ссылки, чей путь пересекается с изменённым. `mut a[1]` не убивает `link` на `a[0]`, но убивает ссылки на `a` целиком.
- **Ссылки не убегают** — функция, принимающая ссылку, читает данные напрямую. Передача ссылки в другую функцию — не цепочка; запрещён побег: возврат, хранение в структуре/списке/замыкании, использование дольше жизни данных. Глубже — через `box` или индекс/арену.
- **`link&`** — ссылка на слот/место: переживает `mut`; существование слота проверяется в рантайме, провал — panic; содержимое слота не анализируется.
- **Внешние операции** — файлы, API, системные вызовы — это просто вызовы внешних функций. Компилятору нужна их сигнатура — как везде.
- **Обработка ошибок** — модель как в Rust (`-> T or E`, проброс `?`, обработка `switch`), содержимое — любой тип, ленивый режим — автогенерация номера ошибки, подробный — пишешь сам.
- **Модули и импорты** — модуль — файл. `use std`, `link file = "file.lang"`, вызов `std.print()` / `file.sum()`, ссылка на ссылку `file::match.sum()`. Цепочки разрешены, циклы — ошибка компиляции. Передача явная. Две гарантии: видишь отдающую и принимающую сторону.
- **Функции как значения** — как везде: можно передать функцию в функцию.
- **Два вида функций** — `fn` отдаёт ответ (обязан быть потреблён: использован или в мусорку), `fn.nothing`/`fn.nil` отдаёт ответ НИЧЕГО (вызов как оператор).
- **Экосистема** — конфиг-формат, компилятор (Cranelift), шаблоны = дженерики, алиасы заменены модификаторами типов. Профилирование: встроенное, механизм зависит от возможностей Cranelift.
- **Сообщения об ошибках компилятора** — мёртвая ссылка объясняется так: «вот эта ссылка, которую ты вот тут используешь, вот тут её вот так убили — то есть при использовании её уже не существует». Формат compile-time ошибки: место использования ссылки → место и способ убийства (`mut`, move, смерть слота) → вывод. Для `link&` с исчезнувшим в рантайме слотом — panic с диагностикой: место использования → слот исчез → panic.
- **`const` — универсальный модификатор «известно на этапе компиляции»** — применим ко всему, что может быть известно или не известно на этапе компиляции: переменные, структуры, функции, шаблоны, циклы, выражения. `const struct` — фиксированные поля и значения, известные компилятору; `struct` — фиксированные типизированные поля, значения известны в рантайме. Динамические словари (maps) в v1 не входят. `const` на цикле — компилятор пытается вычислить результат цикла заранее. Шаблоны и так всегда известны на этапе компиляции, `const` там — подтверждение; выходная функция шаблона может быть рантаймовой.
- **comptime** — метапрограммирование: исполнение кода на этапе компиляции (генерация кода, компиляционные проверки). Отличается от `const`: `const` — «значение известно заранее», comptime — «код выполняется на этапе компиляции».
- **Предупреждения** — переполнение всегда выдаёт предупреждение, релиз/дебаг без разницы. Подавление — `no_warn` перед оператором/выражением/объявлением: подавляет только предупреждения, ошибки — никогда, действует на одну штуку.
- **Комментарии** — `//`.
- **Тесты** — через зоны `---`: отдельная зона тестов.

## Синтаксический сахар

**Брать** (дёшево, ничего не скрывает): интерполяция строк, диапазоны + `for..in`, инклюзивные диапазоны (`0..=n`), `while`, if-выражение, методы (`mut vec.push(x)`), вывод типов, `defer`, `?`, слайсы (`a[1:3]`), кортежи / несколько возвращаемых значений, switch, модификаторы типов (`int:id`), сокращённая запись структур (`{имя, возраст}`), неявный возврат последнего выражения, `break`/`continue`, `else if`, `+=`, явное приведение типов, hex/bin/oct литералы, тесты через зоны `---`, comptime.

**Не брать** (не обязательно): перегрузка операторов, исключения, pattern matching (Rust-style), null-операторы, аргументы по умолчанию / именованные, макросы, интерфейсы/трейты, async/await, корутины/генераторы, рефлексия, GC/RAII, enum с данными (sum types), цепочные сравнения, метки циклов, сырые строки, многострочные строки, указатели (raw pointers) — ссылка (`link`) и есть безопасный указатель, пользовательские паника/ассерты — бизнес-ошибки через `T or E`, panic только для runtime-проверок (ссылки, границы), рекурсивные типы — арена (массив + индексы) покрывает, словари (maps) — не в v1; фиксированный набор полей — `struct`, динамические ключи — позже.

Принцип: не резать функционал. То, что не строим в v1, проектируем так, чтобы можно было добавить потом без поломки.

## Прочее

- Шаблоны = дженерики; шаблоны всегда раскрываются/инлайнятся.
- Enum в конфиге — одинарные обратные кавычки `` `...` ``.
- Формат конфига: строки `""`, числа `''`, массивы `{}`, таблицы `[]`, enum `` `...` ``.
- Комментарии — `//`.
- Переполнение — всегда предупреждение, релиз/дебаг без разницы. Подавление — `no_warn`.
- `no_warn` — префиксный модификатор перед оператором/выражением/объявлением: подавляет предупреждения от того, перед чем стоит. Ошибки подавить нельзя.
