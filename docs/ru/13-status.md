## Что решено по блокам

- **Типы** — статические, 100%. Числовые: `i8/i16/i32/i64`, `u8/u16/u32/u64`, `f32/f64`; `bool`, `str`. `str` — последовательность символов: `s[i]` → `str` из одного символа, `.len` — число символов; `char` и `String` нет, байтовый доступ — позже. Длины и индексы — `i32`, `usize/isize` нет. Метки `i32:id` — уточнение значения, не новый тип; `i32:=id` — привязка к источнику-переменной.
- **Структуры** — способ собрать несколько разных значений в одно, обращение по имени поля.
- **Списки и массивы** — создаются и индексируются как везде.
- **`mut` + операторы** — `mut` и move не смешиваются: `mut` меняет значение, move меняет имя, ответственное за данные. Либо одно, либо другое.
- **Инвалидация вложенных ссылок** — по пути: мутация убивает ссылки, чей путь пересекается с изменённым. `mut a[1]` не убивает `link` на `a[0]`, но убивает ссылки на `a` целиком.
- **Ссылки не убегают** — вычисление или действие, принимающее ссылку, читает данные напрямую. Передача ссылки дальше — не цепочка; запрещён побег: возврат, хранение в структуре/списке/замыкании, использование дольше жизни данных. Глубже — через `box` или индекс/арену.
- **`link&`** — ссылка на слот/место: переживает `mut`; существование слота проверяется в рантайме, провал — panic; содержимое слота не анализируется.
- **Внешние операции** — файлы, API, системные вызовы — это просто вызовы внешнего кода. Компилятору нужна их сигнатура — как везде.
- **Обработка ошибок** — `fn` может вернуть `T or E`; вызывающий обязан сразу обработать результат через `switch`. `?` нет. `sub` ошибку наружу не возвращает. Содержимое — любой тип, ленивый режим — автогенерация номера ошибки, подробный — пишешь сам.
- **Модули и импорты** — модуль — файл. `use std`, `link file = "file.lang"`, вызов `std.print()` / `file.sum()`, ссылка на ссылку `file::match.sum()`. Цепочки разрешены, циклы — ошибка компиляции. Передача явная. Две гарантии: видишь отдающую и принимающую сторону.
- **Вычисления как значения** — `fn` можно передать в `fn` как значение типа `Fn`.
- **Действия не значения** — `sub` нельзя присвоить, передать или вернуть; только вызов как оператор.
- **`fn` и `sub`** — `fn` всегда отдаёт ответ (обязан быть потреблён), `sub` ответа не отдаёт (вызов как оператор).
- **Экосистема** — конфиг-формат, компилятор (Cranelift), алиасы не нужны: метки прямо на типе (`i32:id`). Профилирование: встроенное, механизм зависит от возможностей Cranelift.
- **Сообщения об ошибках компилятора** — мёртвая ссылка объясняется так: «вот эта ссылка, которую ты вот тут используешь, вот тут её вот так убили — то есть при использовании её уже не существует». Формат compile-time ошибки: место использования ссылки → место и способ убийства (`mut`, move, смерть слота) → вывод. Для `link&` с исчезнувшим в рантайме слотом — panic с диагностикой: место использования → слот исчез → panic.
- **`const` — универсальный модификатор «известно на этапе компиляции»** — применим ко всему, что может быть известно или не известно на этапе компиляции: переменные, структуры, вычисления, действия, циклы, выражения. `const struct` — фиксированные переменные и значения, известные компилятору; `struct Name box { variable, ... }` — структура хранит переменные с данными, имена полей — имена переменных; явный тип опционален и должен совпадать с типом переменной. Динамические словари (maps) в v1 не входят. `const` на цикле — компилятор пытается вычислить результат цикла заранее.
- **comptime** — метапрограммирование: исполнение кода на этапе компиляции (генерация кода, компиляционные проверки). Отличается от `const`: `const` — «значение известно заранее», comptime — «код выполняется на этапе компиляции».
- **Предупреждения** — переполнение всегда выдаёт предупреждение, релиз/дебаг без разницы. Подавление — `no_warn` перед оператором/выражением/объявлением: подавляет только предупреждения, ошибки — никогда, действует на одну штуку.
- **Комментарии** — `//`.
- **Тесты** — через зоны `---`: отдельная зона тестов.

## Синтаксический сахар

**Брать** (дёшево, ничего не скрывает): интерполяция строк, диапазоны + `for..in`, инклюзивные диапазоны (`0..=n`), `while`, if-выражение, методы (`mut vec.push(x)`), вывод типов, `defer`, слайсы (`a[1:3]`), кортежи / несколько возвращаемых значений, switch, метки типов (`i32:id`), неявный возврат последнего выражения, `break`/`continue`, `else if`, `+=`, явное приведение типов, hex/bin/oct литералы, тесты через зоны `---`, comptime.

**Не брать** (не обязательно): перегрузка операторов, исключения, pattern matching (Rust-style), null-операторы, аргументы по умолчанию / именованные, макросы, интерфейсы/трейты, async/await, корутины/генераторы, рефлексия, GC/RAII, enum с данными (sum types), цепочные сравнения, метки циклов, сырые строки, многострочные строки, указатели (raw pointers) — ссылка (`link`) и есть безопасный указатель, пользовательские паника/ассерты — бизнес-ошибки через `T or E` у `fn`, panic только для runtime-проверок (ссылки, границы), рекурсивные типы — арена (массив + индексы) покрывает, словари (maps) — не в v1; фиксированный набор полей — `struct`, динамические ключи — позже; чертежи — не в v1: это обычная функция без конкретных типов, отдельной записи для неё нет.

Принцип: не резать функционал. То, что не строим в v1, проектируем так, чтобы можно было добавить потом без поломки.

## Прочее

- Enum в конфиге — одинарные обратные кавычки `` `...` ``.
- Формат конфига: строки `""`, числа `''`, массивы `{}`, таблицы `[]`, enum `` `...` ``.
- Комментарии — `//`.
- Переполнение — всегда предупреждение, релиз/дебаг без разницы. Подавление — `no_warn`.
- `no_warn` — префиксный модификатор перед оператором/выражением/объявлением: подавляет предупреждения от того, перед чем стоит. Ошибки подавить нельзя.
