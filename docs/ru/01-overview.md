# Обзор языка Qvas

## Что это

Низкоуровневый компилируемый язык без GC:

- простой примерно как Go;
- безопасный по памяти не хуже Rust;
- явный как Zig.

Компилятор проверяет программу на этапе компиляции и генерирует обычный низкоуровневый код.

## Цели

- близкая к нативной производительность;
- предсказуемое поведение;
- отсутствие необходимости в тяжёлом runtime/GC;
- автоматическое управление памятью с проверкой ссылок на этапе компиляции;
- максимально простая модель изменения состояния;
- явность важных действий в исходном коде;
- безопасность памяти без необходимости воспроизводить модель Rust один в один.

## Ключевая формула

> **Максимум анализа во время компиляции, минимум обязательной работы во время выполнения.**

Модель изменения состояния:

> **Не «я разрешаю изменять это», а «я изменяю это прямо сейчас».**

## Философия: 10 принципов

1. **Неизменяемость по умолчанию.** Данные не меняются без явного действия.
2. **`mut` обозначает действие.** `mut` — это не постоянное разрешение, а конкретный переход состояния.
3. **Ссылки по умолчанию привязаны к состоянию.** `link b = a` создаёт контракт с текущим состоянием.
4. **Изменение состояния разрывает старые state-bound контракты.** После `mut a = ...` старые обычные ссылки на предыдущее состояние становятся недействительными.
5. **Долгоживущая ссылка должна быть явной.** `link& b = a` выражает привязку к самому объекту/памяти.
6. **Нет состояния по умолчанию: чтение или использование.** Каждое взаимодействие с данными — либо чтение, либо использование. Что именно — определяет контракт операции, куда переданы данные. Чтение — не потребление: читать можно сколько угодно раз.
7. **Память автоматическая, компилятор проверяет ссылки.** Компилятор управляет памятью автоматически и проверяет, что ссылки не переживают объект, на который указывают.
8. **Независимые действия могут выполняться параллельно.** Зависимости образуют граф, который может использоваться для автоматического планирования.
9. **Язык должен быть явным.** Компилятор анализирует семантику, выраженную в программе. Он не должен угадывать намерения программиста там, где это не требуется.
10. **Убирать лишнее, а не резать функционал.** Всё, что реально нужно, остаётся: читать, копировать, перемещать, мутировать, передавать. Убираются только способы сделать это неправильно или избыточно: цепочки ссылок, ссылки, спрятанные в контейнерах, мутация через ссылку.

Это не резание функционала, а очистка: функционал тот же, а способов его испортить — ноль.

## Обучение

Одна из главных целей — чтобы базовую модель языка можно было понять примерно за пять минут и сразу применять. Модель сводится к нескольким правилам:

1. Данные неизменяемы по умолчанию.
2. `mut` — это событие изменения, а не разрешение.
3. Нет состояния по умолчанию: чтение или использование — определяет контракт операции.
4. `let b = a` — копия (создать независимое значение).
5. `link b = a` — ссылка (чтение). `link& b = a` — ссылка на слот (чтение, привязана к памяти). `link* b = a` — ссылка с заморозкой (чтение, данные нельзя изменить, пока ссылка жива).
6. `box(expr)` — использование реальных данных. Компилятор решает: 1 использование → move, 2+ использования → копии.
7. `const a = 10` — константа, значение известно на этапе компиляции.
8. Использование мёртвой ссылки — ошибка компиляции.
9. Ссылка — это чтение: через неё нельзя мутировать.
10. Ссылки прямые, без цепочек; ссылки не прячутся. Функция, принимающая ссылку, — конечный читатель: она не передаёт ссылку дальше.
11. Move убивает ссылки: исходная переменная умерла — ссылки на неё мертвы.
12. Память автоматическая: компилятор сам выделяет и освобождает, проверяет ссылки.
13. Параллелизм: `parallel { ... }` — блок, компилятор строит граф зависимостей и планирует сам *(механизм в разработке)*.
14. Функция отдаёт ответ: `fn` — ответ обязан быть потреблён (использован или в мусорку), `fn.nothing` — ответ НИЧЕГО, вызов как оператор.

Возможны два варианта обучения: для новичков — с базовыми концепциями; для опытных — без повторного объяснения очевидных основ.
