# Синтаксис

## Ключевые слова

| Ключевое слово | Значение |
|---|---|
| `let` | создать переменную |
| `fn` | создать функцию (отдаёт ответ, обязан быть потреблён) |
| `fn.nothing` / `fn.nil` | функция, отдающая ответ НИЧЕГО (вызывается как оператор) |
| `link` | создать ссылку (чтение, умирает при `mut`) или подключить файл (`link file = "file.lang"`) |
| `link&` | долгоживущая ссылка (переживает `mut`) |
| `link*` | долгоживущая ссылка с заморозкой (данные нельзя изменить, пока ссылка жива) |
| `mut` | изменить |
| `box` | использовать данные (компилятор решает копия/move) |
| `const` | константа (значение известно на этапе компиляции) |
| `use` | импорт модуля (std, пакеты) |
| `?` | проброс ошибки одной командой (как в Rust) |

## Переменные

```text
let name = value
let name: type = value
```

Явный тип указывается через двоеточие:

```text
let x = 10
let user: User = get_user()
```

Созданную переменную можно изменить — право есть, потому что создал:

```text
mut x = 15
```

## Функции

```text
fn name(params) -> type { ... }
```

Параметры с типами:

```text
fn sum(box a: int, box b: int) -> int {
    a + b
}
```

`fn` сам создаёт функцию, `let` не нужен.

Два вида функций:

- `fn name(...) -> T` — отдаёт ответ наружу. Ответ обязан быть потреблён: использован или явно отправлен в мусорку (`let delete.trash = ...`).
- `fn.nothing name(...)` (синоним `fn.nil`) — отдаёт ответ НИЧЕГО. Вызывается как оператор, потреблять нечего.

## Условия

```text
if cond { ... } else if ... { ... } else { ... }
```

`if` — выражение (явнее тернарника):

```text
let value = if cond { 1 } else { 2 }
```

## Switch

```text
switch x {
    1 => ...,
    else => ...
}
```

`switch` — выражение, выдаёт значение. Ветвление (выполнить разный код без значения) — через `if`/`else if`. Покрывает 90% нужд pattern matching.

## Циклы

```text
for i in 0..10 { ... }      // диапазон
for item in list { ... }    // по элементам
while cond { ... }          // пока условие истинно
```

Управление:

```text
break
continue
```

## Зоны

Код делится на зоны через `---`:

```text
--- зона 1
код зоны 1

--- зона 2
код зоны 2
```

- `---` — официальный синтаксис языка.
- Зоны плоские: ровно как написано в файле, никуда не вкладываются и не должны.
- На исполнение кода зоны не влияют — это чисто структура, а не поведение.

После `---` на той же строке можно написать что угодно — название или описание зоны:

```text
--- чтение файла
код

--- обработка данных
код
```

Это не комментарий: описание привязано к зоне. Компилятор его видит (разбирает, не выдаёт ошибку), но ничего с ним не делает — как с комментарием: знать не надо, и всё.

Главная цель зон — отделить импорты от приёма/передачи и от кода, чтобы это было мега очевидно. Сейчас компилятор зоны разбирает, но не использует — это просто удобство. В будущем, возможно, компилятор сможет размечать зоны в AST на более мелкие структуры и взаимодействовать с ними.

Принятый порядок в файле: сначала зона `use` (импорты), затем зона `link file` (подключение файлов), затем код. Так `link` не путается: в зоне импортов `link file = "..."` — это подключение файла, а в коде `link b = a` — это ссылка. Это порядок, который язык предлагает использовать; не хочешь — не запрещается, но потом сам разберёшься, где что.
