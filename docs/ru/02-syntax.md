# Синтаксис Qvas

## Ключевые слова

| Ключевое слово | Значение |
|---|---|
| `let` | создать переменную |
| `fn` | вычисление: отдаёт ответ, ответ обязан быть потреблён |
| `sub` | действие: отдаёт чек — информацию, куда ушли данные |
| `link` | создать ссылку (чтение, умирает при `mut`) и подключить файл (`link file = "file.lang"`) |
| `link&` | долгоживущая ссылка на слот (переживает `mut`, существование слота проверка или статика) |
| `link*` | ссылка с заморозкой (данные нельзя изменить, пока ссылка жива) |
| `mut` | изменить |
| `box` | использовать данные (принцип работы далее) |
| `const` | константа (значение известно на этапе компиляции) |
| `use` | импорт модуля (std, пакеты) |

## Переменные

```text
let name = value
let name: type = value
```

Явный тип указывается через двоеточие:

```text
let x = 10
let user: str = get_user()
```

Созданную переменную можно изменить:

```text
mut x = 15
```

`mut` стоит и перед мутирующим вызовом — изменением владеет переменная, метод её меняет:

```text
mut tokens.push(token)     // дописали в список
let top = mut stack.pop()  // сняли со стека: мутирующий вызов возвращает значение
```

Изменяет переменная: `push` меняет `tokens`, `pop` меняет `stack` и отдаёт снятое значение как обычный ответ.


## Строки

`"..."` — строковый литерал типа `str`. Других строковых литералов нет.

`str` — последовательность символов: `s[i]` даёт `str` из одного символа, `s.len` — число символов. Отдельного `char` нет, `String` тоже нет.

```text
let s: str = "abc"
let c = s[0]        // c: str, "a"
```


## Структуры

Структура создаётся только так:

```text
struct Person[] box {
    id: i32
}
```

`Person` — имя структуры, `id` — поле. Квадратные скобки `[]` нужны для указателей, логика которых описывается в [здесь](15-index-and-structs.md).


## Вычисления и действия

Две разные сущности, не взаимозаменяемые:

```text
fn name(params) -> type or E { ... }
sub name(params) { ... }
```

`fn` объявляет вычисление: отдаёт ответ. `sub` объявляет действие: с `or E` отдаёт чек — информацию, куда ушли данные. Ответ `fn` обязан быть потреблён.

```text
use std

fn sum(box a: i32, box b: i32) -> i32 {
    a + b
}

sub main() -> Sys {
    let r = sum(box(3, 5))
    ignore!(std.print(r))
}
```

- Ответ `fn` обязан быть потреблён: связан, использован, передан или возвращён. Голый вызов `fn` — ошибка.
- Чек `sub` — информация о том, куда ушли данные. Нужен — свяжи или разбери; не нужен — не бери или `ignore!`.
- `sub` без `or E` не может не сработать: ошибки нет, вызов как оператор.
- `ignore!` — явно не брать чек: `ignore!(print(x))`.
- `out` — параметр записи в чужую память: `read_into(path, out(buf))`.
- `fn` не вызывает `sub`: вычисление не выполняет действий. Вызов идёт только в одну сторону — `sub` вызывает `fn`, но не наоборот.
- `fn` может вернуть `T or E`; вызывающий обязан сразу разобрать результат на вызове через `switch` или `match`. Проброса нет.
- `fn` может быть значением типа `Fn`; `sub` значением не является.
- `main() -> Sys` это указание, куда уходят данные, а не тип возврата. `Sys` — приёмник, не тип. Для встраиваемых систем приёмник другой, имя даёт платформа.


## Сахар

Форма с `!` — удобная запись, а не новая сущность:

```text
getline!(line)
```

Раскрытие видно в IDE и документации. Тег берётся из раскрытия: если внутри действие — форма действие, из `fn` её звать нельзя.


## Шаблоны и чертежи

Шаблон — готовая функция с конкретной сигнатурой: все типы известны, её можно вызывать как есть.

Чертёж — функция без конкретных типов: вместо них оставлены места. Отдельного синтаксиса нет; после заполнения мест получается шаблон.
**В других языках это называют generics функцией, от чего я отказываюсь. Название бессмысленное, а это плохо и вводит бесполезные сущности.**

Чертежи не входят в v1.


## Условия

```text
if cond {
    ... 
  } else if ... {
    ... 
  } else {
    ... 
  }
```

`if` — выражение (явнее тернарника):

```text
let value = if cond { 1 } else { 2 }
```


## Enum

`enum` — выбор: одно из перечисленных, второе выбрать нельзя. Вариант может нести свои данные:

```text
enum Shape {
    Circle(f64),
    Empty,
    Rect(f64, f64),
}
```

`Circle` несёт одно число, `Rect` — два, `Empty` — ничего. Данные принадлежат варианту: у `Circle` есть только радиус, у `Rect` — только ширина и высота. Собрать круг с шириной нельзя.

Без данных вариант — просто метка: `enum TokenKind { Num, Add, Mul }`.


## Switch

```text
switch x {
    1 => ...,
    else => ...
}
```

`switch` — выражение, выдаёт значение. Сравнивает обычные значения: числа, строки, метки вариантов без данных. Ветка по умолчанию — `else`. Ветвление (выполнить разный код без значения) — через `if`/`else if`.


## Match

```text
let area = match shape {
    Circle(r) => 3.14 * r * r,
    Rect(w, h) => w * h,
    Empty => 0,
}
```

`match` — выражение. Он смотрит на вариант и даёт доступ к данным этого варианта: `r`, `w`, `h` — имена для чтения, живут только внутри своей ветки. Данные не копируются и не забираются, `match` только читает.

- Перебор обязан быть полным: все варианты перечислены. Забыть ветку — ошибка компиляции. `else` не нужен.
- Внутри ветки видно только её данные: в ветке `Circle` есть `r`, но нет `w`.
- Имена `r`, `w`, `h` — только для чтения, за пределы ветки не выходят.

`switch` сравнивает значения, `match` разбирает варианты. Для вариантов без данных подходит любой; `match` нужен там, где у варианта есть данные.

```text
for item in list { ... }    // по элементам

```

```text

```

## Зоны

Код делится на зоны через `---`:

```text
--- зона 1
код зоны 1

--- зона 2
код зоны 2
```

- `---` — официальный синтаксис языка.
- Зоны плоские: ровно как написано в файле, никуда не вкладываются и не должны.
- На исполнение кода зоны не влияют — это чисто структура, а не поведение.

После `---` на той же строке можно написать что угодно — название или описание зоны:

```text
--- чтение файла
код

--- обработка данных
код
```

Это не комментарий: описание привязано к зоне. Компилятор его видит (разбирает, не выдаёт ошибку), ничего с ним не делает.

Главная цель зон — отделить импорты от приёма/передачи и от кода, чтобы это было мега очевидно. Сейчас компилятор зоны разбирает. Разметку могут использовать инструменты: например, отдельная зона тестов. В будущем, возможно, компилятор сможет размечать зоны в AST на более мелкие структуры и взаимодействовать с ними.

Принятый порядок в файле: сначала зона `use` (импорты), затем зона `link file` (подключение файлов), затем код. Так `link` не путается: в зоне импортов `link file = "..."` — это подключение файла, а в коде `link b = a` — это ссылка. Это порядок, который язык предлагает использовать.
