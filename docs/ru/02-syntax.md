# Синтаксис

## Ключевые слова

| Ключевое слово | Значение |
|---|---|
| `let` | создать переменную |
| `fn` | вычисление: отдаёт ответ, ответ обязан быть потреблён |
| `sub` | действие: ответа нет, вызывается как оператор |
| `link` | создать ссылку (чтение, умирает при `mut`) или подключить файл (`link file = "file.lang"`) |
| `link&` | долгоживущая ссылка на слот (переживает `mut`, существование слота проверяется в рантайме) |
| `link*` | долгоживущая ссылка с заморозкой (данные нельзя изменить, пока ссылка жива) |
| `mut` | изменить |
| `box` | использовать данные (компилятор решает копия/move) |
| `const` | константа (значение известно на этапе компиляции) |
| `use` | импорт модуля (std, пакеты) |

## Переменные

```text
let name = value
let name: type = value
```

Явный тип указывается через двоеточие:

```text
let x = 10
let user: User = get_user()
```

Созданную переменную можно изменить — право есть, потому что создал:

```text
mut x = 15
```

## Строки

`"..."` — строковый литерал типа `str`. Других строковых литералов нет.

`str` — последовательность символов: `s[i]` даёт `str` из одного символа, `s.len` — число символов. Отдельного `char` нет, `String` тоже нет.

```text
let s: str = "abc"
let c = s[0]        // c: str, "a"
```

## Структуры

Структура создаётся только так:

```text
struct Person box {
    x,
}
```

`Person` — имя структуры, `x` — переменная. Структура хранит переменные с данными, а не отдельные поля: имя поля — это имя переменной. Тип писать не нужно — он уже известен из переменной. Если указать его явно, он должен совпадать с типом переменной. `box` обязателен.

## Вычисления и действия

Две разные сущности, не взаимозаменяемые:

```text
fn name(params) -> type { ... }
sub name(params) { ... }
```

`fn` объявляет вычисление: у него всегда есть ответ. `sub` объявляет действие: ответа нет, вызов идёт как оператор. `let` не нужен ни там, ни там.

```text
fn sum(box a: i32, box b: i32) -> i32 {
    a + b
}

sub main() {
    let r = sum(box(3, 5))
    std.print(r)
}
```

- Ответ `fn` обязан быть потреблён: связан, использован, передан или возвращён. Голый вызов `fn` — ошибка.
- `sub` не даёт ответа. Его нельзя присвоить, передать, вернуть или использовать в выражении. Только вызов как оператор.
- `fn` не вызывает `sub`: вычисление не выполняет действий. Вызов идёт только в одну сторону — `sub` вызывает `fn`, но не наоборот.
- `fn` может вернуть `T or E`; вызывающий обязан сразу обработать результат через `switch`. `sub` ошибку наружу не отдаёт.
- `fn` может быть значением типа `Fn`; `sub` значением не является.

## Шаблоны и чертежи

Шаблон — готовая функция с конкретной сигнатурой: все типы известны, её можно вызывать как есть.

Чертёж — функция без конкретных типов: вместо них оставлены места. Отдельного синтаксиса нет; после заполнения мест получается шаблон.

Чертежи не входят в v1.

## Условия

```text
if cond { ... } else if ... { ... } else { ... }
```

`if` — выражение (явнее тернарника):

```text
let value = if cond { 1 } else { 2 }
```

## Switch

```text
switch x {
    1 => ...,
    else => ...
}
```

`switch` — выражение, выдаёт значение. Ветвление (выполнить разный код без значения) — через `if`/`else if`. Покрывает 90% нужд pattern matching.

## Циклы

```text
for i in 0..10 { ... }      // диапазон
for item in list { ... }    // по элементам
while cond { ... }          // пока условие истинно
```

Управление:

```text
break
continue
```

## Зоны

Код делится на зоны через `---`:

```text
--- зона 1
код зоны 1

--- зона 2
код зоны 2
```

- `---` — официальный синтаксис языка.
- Зоны плоские: ровно как написано в файле, никуда не вкладываются и не должны.
- На исполнение кода зоны не влияют — это чисто структура, а не поведение.

После `---` на той же строке можно написать что угодно — название или описание зоны:

```text
--- чтение файла
код

--- обработка данных
код
```

Это не комментарий: описание привязано к зоне. Компилятор его видит (разбирает, не выдаёт ошибку), но ничего с ним не делает — как с комментарием: знать не надо, и всё.

Главная цель зон — отделить импорты от приёма/передачи и от кода, чтобы это было мега очевидно. Сейчас компилятор зоны разбирает, но на исполнение кода они не влияют — это структура и удобство. Разметку могут использовать инструменты: например, отдельная зона тестов. В будущем, возможно, компилятор сможет размечать зоны в AST на более мелкие структуры и взаимодействовать с ними.

Принятый порядок в файле: сначала зона `use` (импорты), затем зона `link file` (подключение файлов), затем код. Так `link` не путается: в зоне импортов `link file = "..."` — это подключение файла, а в коде `link b = a` — это ссылка. Это порядок, который язык предлагает использовать; не хочешь — не запрещается, но потом сам разберёшься, где что.
