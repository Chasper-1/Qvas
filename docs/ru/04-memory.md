# Память

## Автоматическое управление

Памятью управляет компилятор. Программист не пишет `alloc` и `free` — компилятор сам решает, где выделить (стек или куча, escape analysis) и когда освободить.

Освобождение — в точке последнего использования данных (как NLL в Rust). Анализ времён жизни, который проверяет ссылки, и так знает, когда данные мертвы: вставка `free` не требует отдельного прохода.

Автоматическое управление детерминированное: никакого GC, никакого подсчёта ссылок, никаких пауз. Это просто компиляторные `free` в известных точках.

## Компилятор проверяет ссылки

Компилятор проверяет ссылки: ссылка не может пережить объект/слот, на который указывает. Данные умирают в точке последнего использования (или в конце области видимости), и ссылка не может использоваться после этого. Жизнь базы проверяется статически; существование слота для `link&` — в рантайме, если оно зависит от данных.

```text
let a = ...
link b = a        // ссылка на значение
ignore!(std.print(b))  // последнее использование данных
// здесь данные мертвы — компилятор освободил память
```

Ссылаться на то, чего нет, нельзя по определению. Если смерть слота доказуема, это ошибка компиляции. Для `link&` слот может исчезнуть только в рантайме (например, элемент удалён из контейнера) — тогда компилятор вставляет проверку существования слота, и провал проверки — panic, а не UB.

## Перемещение и копия

`let b = a` — всегда копия (явное намерение программиста). `box(a)` — компилятор решает копия или move.

Считаются только **потребляющие** использования (`box`). Чтения через ссылки (`link`) не считаются — читать можно сколько угодно раз, это не потребление.

Это передача, а не владение: ответственное имя меняется, старое имя мертво, память не перемещается. Вместе со старым именем умирают и ссылки на него.

Для больших объектов копия может быть дорогой; оптимизатор может превращать безопасные копии в перемещения, но решение принимает компилятор, а не программист.


## Логические ошибки — ответственность кода

Компилятор гарантирует безопасность памяти: мёртвая ссылка не может быть использована. Если смерть доказуема, это ошибка компиляции. Логические ошибки компилятор не решает:

```text
let a = 10
link& b = a

mut a = new_object
```

С памятью всё в порядке: `b` жива, слот жив, `b` видит новое значение. Но если `b` ожидала данные старого объекта — это семантическая ошибка кода, а не языка. Если же слот перестал существовать (например, элемент удалён из контейнера), срабатывает runtime-проверка `link&` — panic.
