# Память

## Автоматическое управление

Памятью управляет компилятор. Программист не пишет `alloc` и `free` — компилятор сам решает, где выделить (стек или куча, escape analysis) и когда освободить.

Освобождение — в точке последнего использования данных (как NLL в Rust). Анализ времён жизни, который проверяет ссылки, и так знает, когда данные мертвы: вставка `free` не требует отдельного прохода.

Автоматическое управление детерминированное: никакого GC, никакого подсчёта ссылок, никаких пауз. Это просто компиляторные `free` в известных точках.

## Компилятор проверяет ссылки

Компилятор проверяет ссылки: ссылка не может пережить объект, на который указывает. Данные умирают в точке последнего использования (или в конце области видимости), и ссылка не может использоваться после этого.

```text
let a = ...
link b = a        # ссылка на значение
std.print(b)      # последнее использование данных
# здесь данные мертвы — компилятор освободил память
```

Ссылаться на то, чего нет, нельзя по определению. Это ошибка компиляции, а не runtime-проверка.

## Почему автоматическое управление

Программист не должен думать о памяти, когда она и так работает детерминированно. Ручное выделение требует знать, где именно нужна память, а ошибка в этом месте — логическая, компилятор её не ловит.

Автоматическое управление + проверка ссылок дают:

- предсказуемое поведение — освобождение в точке последнего использования, без пауз и сборщика;
- простые проверки — анализ времён жизни и так нужен для проверки ссылок, вставка `free` бесплатна;
- безопасность памяти — компилятор сам решает, где выделить и когда освободить.

Цель языка — не дать стрелять себе в ногу при написании. Компилятор ловит очевидные ошибки на этапе компиляции и сам управляет памятью.

## Перемещение и копия

`let b = a` — всегда копия (явное намерение программиста). `box(a)` — компилятор решает копия или move.

Правило для `box`:

- данные используются один раз → move: данные переезжают под новое имя, старое имя умирает;
- данные используются 2+ раза → копии, чистого move не будет: создаются независимые значения.

Считаются только **потребляющие** использования (`box`). Чтения через ссылки (`link`) не считаются — читать можно сколько угодно раз, это не потребление.

Это передача, а не владение. Владение — это передача плюс много лишнего. Передача — это передача, не больше и не меньше: данные переехали, старое имя мертво. Вместе со старым именем умирают и ссылки на него.

Для больших объектов копия может быть дорогой; оптимизатор может превращать безопасные копии в перемещения, но решение принимает компилятор, а не программист.
