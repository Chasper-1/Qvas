# Указатель, структуры и направление ссылок

## Указатель (`index`)

**Определение.** Указатель — значение, которое содержит сведения о том, где находятся другие данные. Сами данные он не содержит и доступа к ним не даёт. Это информация о местоположении.

**Запись.** `index`, сокращения: `idx`, `ind`, `indx`, `inx`.

**Применение.** Только данные и структуры. Назначение — строить связные штуки: связные списки, графы, деревья. В Qvas — через арену: массив + индексы.

**Свойства:**

- обычное значение;
- не ссылка: живость не проверяется, `mut` его не убивает;
- копируется как значение, хранится в структурах и списках;
- доступ к данным — только через контейнер: `nodes[i]`;
- с ним ничего нельзя сделать: ни разыменовать, ни изменить данные через него;
- проверять надо только то, что он передаёт (существует ли слот в момент чтения), а не его логику.

**Чем не является:**

- не `link` / `link&` / `link*` — те дают окно в данные и проверяются;
- не сырой указатель — сырых указателей в языке нет;
- не владение и не ответственное имя.

## Структура с указателями

Правило: `()` — действие/вызов, `[]` — место/данные. Параметры структуры объявляются в квадратных скобках.

```text
struct Node[right_i: nodes[indx], left_i: nodes[indx]] box {
    id:    i32
    link& right: right_i
    link& left:  left_i
}
```

Читается построчно:

- `right_i: nodes[indx]` — указатель: индекс в `nodes`;
- `link& right: right_i` — ссылка через этот указатель;
- `id: i32` — обычные данные;
- `indx` — метка индекса, `nodes` — контейнер, `Node` — тип структуры.

Три части структуры:

| Часть | Где | Что содержит |
|---|---|---|
| адресация | `[...]` | указатели: куда узел смотрит |
| данные | тело | то, что лежит в узле |
| связи | тело | ссылки, созданные через указатели |

### Ссылка создаётся на месте

Ссылка объявляется прямо в структуре и наружу не выходит: не передаётся в структуру снаружи, не извлекается, не возвращается, не хранится в другом месте. Родилась внутри — умерла вместе со структурой.

Это не нарушает принцип «ссылки не прячутся»: запрещён пронос ссылки в контейнер извне, а не создание внутри.

Указатель ничего не стоит. Он лишь прокидывает ссылку, которая создаётся внутри и там же умирает.

### Порядок

1. В `[...]` передаётся указатель — `right_i: nodes[indx]`.
2. Указатель привязывается к ссылке — `link& right: right_i`.
3. Через ссылку читаются конкретные данные — `right`.

## Направление ссылок

`main` — уровень 0. Функция, вызванная из `main`, — уровень 1, её вызванная — уровень 2. Уровень — глубина вызова.

- Ссылка рождается на уровне N.
- Читать её можно только на уровнях выше N — внутри вызовов, растущих из места создания.
- Передача — по одному шагу за вызов: N → N+1 → N+2.
- Вниз, к вызывающему (N-1, N-2), — нельзя.
- Вбок, в другую ветку вызовов, — нельзя.

**Почему это работает.** Кадр N жив, пока живёт любой кадр N+k. Значит данные, на которые ссылка смотрит, гарантированно живы на каждом использовании. В обратную сторону гарантии нет: кадр N-1 переживёт N, и ссылка станет мёртвой. Отсюда запрет вниз.

**Проверка.** На каждом вызове проверяется одно: место создания ссылки — предок места вызова. Функция проверяется один раз, вызовы — по одному ребру. Длинных цепочек и вывода времён жизни на весь граф не нужно.

**Следствия:**

- рекурсия — вызов себя это шаг вверх; вернуть ссылку из рекурсии нельзя, читать внутри можно;
- `Fn`-значения — вызов через переменную всё равно ребро вызова; ссылка в замыкание не кладётся;
- `parallel {}` — уровень по стеку не работает; ссылка создаётся в кадре-предке блока, внутри — только чтение, `link*` как гарантия.

## Мутация и выбор ссылки

| | `link` | `link&` | `link*` |
|---|---|---|---|
| После `mut` | умирает | живёт | `mut` запрещён |
| Что читает | старое состояние | текущий слот | замороженное состояние |
| Смысл связи | фиксирован | может разойтись с данными | всегда совпадает |
| Проверка | статика | статика, иначе runtime | статика |
| Стоимость | 0 | возможен runtime | 0 |

Инвалидация идёт по пути: `mut parent.left` не убивает `link` на `node`, потому что пути не пересекаются. Поэтому при перебалансировке связи соседей меняются, а ссылки на сами узлы живут.

## Где нужен `link&`

Только когда сам путь мутируется, а читать его надо продолжать:

1. **Накопитель в цикле** — ссылка на поле, которое меняется каждую итерацию.
2. **Элемент, переживающий изменение контейнера** — `link& item = list[i]`, затем `mut list.push(...)`; `link` умер бы, `link*` запретил бы `push`.
3. **Наблюдатель за полем** — кэш, счётчик, текущий выбранный элемент: долгоживущая ссылка, которая должна видеть новое значение.

Не нужен для деревьев и графов: там связи пересоздаются, а пути соседей не пересекаются — достаточно обычного `link`.

**Правило выбора:**

- путь не мутируется → `link` (или `link*`, если нужна гарантия неизменности);
- путь мутируется, ссылку можно пересоздать → `link`, пересоздать;
- путь мутируется часто, пересоздавать неудобно или дорого по коду → `link&`;
- нужна гарантия, что данные не изменятся → `link*`;
- нужна живая связь при изменении на месте → `link&` с runtime-проверкой и риском расхождения смысла.

`link&` — не для деревьев и графов, а для живого наблюдения за изменяемым слотом.

## Графы: режимы

1. **Сборка** — только индексы, мутация разрешена, узлы достраиваются.
2. **Заморозка** — создаются структуры с `link*` на детей; арена не мутируется, пока жива хоть одна такая структура.
3. **Чтение** — обход, параллельное чтение, без проверок и паник.

Изменение графа = новая версия: убрать `link*`-структуры, мутировать арену, собрать заново.

## Стоимость `link&`

Runtime-проверка нужна только там, где статика не доказала существование слота:

| Ситуация | Проверка |
|---|---|
| слот — локальная переменная в области видимости | статика, runtime нет |
| слот — поле живой структуры | статика, runtime нет |
| слот может исчезнуть по данным (`pop`, `clear`, `remove`) | runtime |
| индекс приходит извне и может быть вне границ | runtime |

Мутация сама по себе цены не добавляет: ссылка только читает, а точка изменения известна. Видно либо 3, либо 4 — полузаписанного состояния нет, память безопасна.

В параллельном исполнении порядка нет, и «момент мутации известен» перестаёт быть бесплатным: нужен `link*` (заморозка) либо явная синхронизация.
