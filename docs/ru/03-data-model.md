# Модель данных

## Механизмы работы с данными

| Механизм | Значение | Что происходит |
|---|---|---|
| `let b = a` | копия | создать независимое значение, `a` жива |
| `link b = a` | ссылка | чтение, `a` жива, умирает при `mut a` |
| `link& b = a` | ссылка на слот | чтение, привязана к памяти, переживает `mut a` |
| `link* b = a` | ссылка с заморозкой | чтение, привязана к памяти, `mut a` запрещён, пока ссылка жива |
| `databox(expr)` | реальные данные | компилятор выбирает копия или move |

Контракт операции определяет, что принимает операция: ссылку (чтение) или databox (использование). Все операции проверяются компилятором. Использование мёртвой ссылки любого типа — ошибка компиляции.

## Нет состояния по умолчанию

Каждое взаимодействие с данными — либо чтение, либо использование. Нет «по умолчанию».

```text
let b = a
```

создаёт копию. `b` — независимое значение, `a` жива.

```text
link b = a
```

создаёт ссылку. `b` читает данные, `a` жива.

```text
let sum = databox(a + b)
```

использует реальные данные. Компилятор выбирает копия или move по числу использований:

- 1 использование → move;
- 2+ использования → копии, чистого move не будет.

```text
let result = add(a, b)                    # чтение — ссылки, без databox
let result = add(databox(a, b))           # использование — databox
```

### Чтение — это не потребление

Чтение реализуется через ссылку (`link` или `link&`), ничего не изменяет и ничего не потребляет. Читать можно сколько угодно раз.

Потребление — это передача данных через databox. Компилятор решает: копия или move, в зависимости от числа использований.

> Чтение — это только посмотреть. Взять — это databox.

## Контракты операций

Контракт у операции, а не у значения. Каждая операция заранее объявляет, читает она или потребляет. Без угадывания — гарантия написана.

**Читают (принимают ссылку, на вызове ничего писать не надо):**

- `print`, вывод;
- длина, `isEmpty`, `contains` и прочие проверки;
- сравнения (`==`, `!=`, `<`, `>`, `<=`, `>=`);
- условия (`if cond`);
- чтение по индексу (`a[0]`);
- итерация (`for item in list` — читает список, `item` — ссылка).

**Потребляют (требуют `databox`):**

- арифметика (`a + b`, `a * b` — создают новое значение из данных);
- конкатенация строк;
- `push` в список, вставка, хранение в структуру;
- передача в потребляющую функцию (параметр `databox`);
- `return` — передача данных назад.

**Остальное решается на месте.** Слайсы, строки и составные значения сами по себе ничего не делают: куда передал — тот контракт и действует. В ссылку — читается, в `databox` — потребляется. Однозначного ответа «слайс это чтение или потребление» нет и не нужно.

**Пользовательские функции** список не требуют: контракт в сигнатуре — `link` = чтение, `databox` = потребление. Видно сразу.

## Мутация разрывает state-bound контракт

```text
let a = 20
link b = a
```

Оба имени связаны с одним текущим состоянием данных. Связь `link b = a` — контракт с конкретным состоянием: `b` имеет право обращаться к текущему состоянию `a`.

Если затем происходит:

```text
mut a = 30
```

создаётся новое состояние. Старый контракт `link b = a₀` больше не существует. `b` не превращается в dangling reference — старая версия состояния просто перестаёт быть допустимой для дальнейшего использования через этот контракт. Использование `b` после `mut a` — ошибка компиляции.

Чтобы снова получить `b`, необходимо явно написать:

```text
link b = a
```

## `link& b = a` — явная долговременная ссылка

Отдельный синтаксис для ссылки, которая привязана не к конкретной версии состояния, а к самой памяти/слоту:

```text
let a = 20
link& b = a

mut a = 30
```

В этом случае `b` остаётся связанной с той же памятью и после изменения `a` видит новое значение.

Разница:

```text
link b = a
```

— ссылка на конкретное состояние.

```text
link& b = a
```

— явная привязка к самому слоту/памяти.

`link&` не делает ссылку бессмертной: когда слот умирает (например, переменная выходит из области видимости или объект освобождается), ссылка умирает вместе с ним. Использование `link&`-ссылки после смерти слота — ошибка компиляции.

Главная идея:

> Обычная ссылка короткоживущая и привязана к состоянию. Долгоживущая ссылка должна быть выражена отдельным синтаксисом.

## `link* b = a` — ссылка с заморозкой

`link*` — самая сильная гарантия: пока ссылка жива, данные, на которые она указывает, нельзя изменить вообще. Ни через ссылку, ни через оригинал.

```text
let a = 20
link* b = a

mut a = 30    # ОШИБКА: a заморожена, пока жива link* b
```

Когда `link*` умирает (вместе со слотом, как `link&`), заморозка снимается.

Разница:

```text
link& b = a    # «я хочу видеть изменения слота» — mut a можно, b следует за изменениями
link* b = a    # «данные не изменятся, пока я смотрю» — mut a запрещён
```

Зачем нужен `link*`:
- параллельный доступ — несколько потоков читают, никто не мутирует;
- инварианты — данные не изменятся, пока обрабатываются;
- кэширование — значение гарантированно валидно.

Использование мёртвой `link*` — ошибка компиляции, как и любой другой ссылки.

Контроль привязан к потребителю, а не к данным: пока данных никто не читает — они свободны. Появился потребитель (`link*`) — данные заморожены. Ссылка умерла — контроль выключился.

## Ссылки на элементы

Ссылка может быть создана непосредственно на нужный элемент:

```text
link b = a[0]
```

означает ссылку на соответствующий элемент текущего состояния.

Если `a` затем изменяется (`mut a = ...`), обычная связь с предыдущим состоянием `a[0]` прекращается. Даже если после изменения в `a[0]` случайно находится такое же значение, это уже новое состояние.

Инвалидация при мутации — целого объекта: любая мутация `a` убивает все state-bound ссылки, производные от `a`, включая ссылки на элементы. Если необходимо сохранить привязку к самой памяти, используется долговременная форма ссылки.

## Ссылки прямые, без цепочек

Ссылка всегда указывает прямо на данные. Ссылку можно создать только от переменной, в которой лежат данные. От другой ссылки — нельзя:

```text
link b = a
link c = b    # запрещено: ссылка от ссылки
```

Хочешь ссылку на данные — пиши прямо на переменную с данными:

```text
link c = a    # правильно
```

Цепочки невозможны в принципе — не потому что компилятор их ловит, а потому что их нельзя написать. Ссылка всегда указывает прямо на данные, и это гарантировано самим языком.

## Ссылка не пробрасывается через функции

Функция, принимающая ссылку, — конечный читатель: она читает данные напрямую и не передаёт ссылку в другую функцию, принимающую ссылку. Проброс ссылки через вызов — это та же цепочка, только спрятанная за именем функции.

```text
fn.nothing read(link data: Data) { ... }   # конечный читатель: читает напрямую
```

Если функция принимает ссылку и передаёт её в другую функцию, принимающую ссылку, — это цепочка, запрещено. Нужно передать данные глубже — через `databox` (копия или move), а не через ссылку.

## Ссылки не прячутся

Ссылка короткоживущая: живёт там, где создана, и умирает там же. Ссылку не кладут в списки и не хранят в других местах — это не делается.

Если данные нужны кому-то надолго — их не прячут в ссылку, а передают через databox (move или копия). Данные либо у тебя, либо переданы другому, либо скопированы. Третьего не дано.

## Move убивает ссылки

При перемещении (когда databox решает move) исходная переменная умирает — данные переехали под новое имя. Вместе с ней умирают все ссылки на неё:

```text
let a = big_object
link b = a            # ссылка на a
let c = databox(a)    # a: 1 использование → move, a мертва
print(b)              # ошибка: b мертва вместе с a
```

Правило простое: исходная переменная умерла — ссылки на неё мертвы.

## Копия и независимость

`let b = a` — **всегда копия**. Это явное намерение программиста: «мне нужна независимая копия». `a` остаётся жива.

`b` и `a` больше никак не связаны: мутация `a` не влияет на `b`, и наоборот. Копия — единственный способ получить независимое значение.

Копия делается от переменной с данными: `let c = a`, а не через ссылку.

`databox` — другое: компилятор решает копия или move по числу **потребляющих** использований. Чтения через ссылки (`link`) не считаются — читать можно сколько угодно раз, это не потребление.

## Выбор механизма — заявка на намерение

Выбор механизма выражает намерение программиста:

- `let b = a` — «мне нужна независимая копия»;
- `link b = a` — «мне нужно прочитать данные»;
- `link& b = a` — «я хочу видеть изменения слота»;
- `databox(expr)` — «я использую реальные данные, компилятор решит копия или move».

Контракт операции определяет, что принимать: ссылку (чтение) или databox (использование). Если планируется замена объекта, компилятор поймает любое использование после неё.

## Ссылка — это чтение

Через ссылку можно только читать. Изменить или мутировать через ссылку нельзя — это не её функция. Мутация — это `mut` на самой переменной, где лежат данные. Ссылка на это не способна в принципе.

Ссылка безопасна по определению: через неё физически нельзя ничего сломать, потому что она только читает. И она умирает при мутации, потому что данные, на которые она смотрела, изменились, — а она читала старое состояние. `link*` усиливает это до заморозки: пока ссылка жива, данные нельзя изменить даже через оригинал.

## Логические ошибки — ответственность кода

Компилятор гарантирует безопасность памяти: мёртвая ссылка любого типа не может быть использована. Логические ошибки компилятор не решает:

```text
let a = 10
link& b = a

mut a = new_object
```

С памятью всё в порядке: `b` жива, слот жив, `b` видит новое значение. Но если `b` ожидала данные старого объекта — это семантическая ошибка кода, а не языка.
