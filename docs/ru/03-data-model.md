# Модель данных

## Механизмы работы с данными

| Механизм | Значение | Что происходит |
|---|---|---|
| `let b = a` | копия | создать независимое значение, `a` жива |
| `link b = a` | ссылка | чтение, `a` жива, умирает при `mut a` |
| `link& b = a` | ссылка на слот | чтение, привязана к слоту/месту, переживает `mut a`; существование слота проверяется в рантайме, провал → panic |
| `link* b = a` | ссылка с заморозкой | чтение, привязана к слоту/месту, `mut a` запрещён, пока ссылка жива; проверка статическая |
| `box(expr)` | реальные данные | компилятор выбирает копия или move |

Контракт операции определяет, что принимает операция: ссылку (чтение) или box (использование). Все операции проверяются компилятором. Использование мёртвой ссылки — ошибка: если смерть доказуема, ошибка компиляции; для `link&` с исчезнувшим в рантайме слотом — panic.

## Нет состояния по умолчанию

Каждое взаимодействие с данными — либо чтение, либо использование. Нет «по умолчанию».

```text
let b = a
```

создаёт копию. `b` — независимое значение, `a` жива.

```text
link b = a
```

создаёт ссылку. `b` читает данные, `a` жива.

```text
let sum = box(a + b)
```

использует реальные данные. Компилятор выбирает копия или move по числу потребляющих использований:

- 1 использование → move: данные не копируются, старое имя умирает;
- 2+ использования → копии: все использования, кроме максимум одного, становятся копиями. Move может быть назначен на фактически последнее использование, но не гарантирован — зависит от кода. Двух move не бывает.

Память при move не перемещается: меняется только имя, ответственное за данные.

```text
let result = add(a, b)                // чтение — ссылки, без box
let result = add(box(a, b))           // использование — box
```

### Чтение — это не потребление

Чтение реализуется через ссылку (`link`, `link&` или `link*`), ничего не изменяет и ничего не потребляет. Читать можно сколько угодно раз.

Потребление — это передача данных через box. Компилятор решает: копия или move, по числу потребляющих использований (правило выше).

> Чтение — это только посмотреть. Взять — это box.

## Контракты операций

Контракт у операции, а не у значения. Каждая операция заранее объявляет, читает она или потребляет. Без угадывания — гарантия написана.

**Читают (принимают ссылку, на вызове ничего писать не надо):**

- `print`, вывод;
- длина, `isEmpty`, `contains` и прочие проверки;
- сравнения (`==`, `!=`, `<`, `>`, `<=`, `>=`);
- условия (`if cond`);
- чтение по индексу (`a[0]`);
- итерация (`for item in list` — читает список, `item` — ссылка).

**Потребляют (требуют `box`):**

- арифметика (`a + b`, `a * b` — создают новое значение из данных);
- конкатенация строк;
- `push` в список, вставка, хранение в структуру;
- передача в потребляющую функцию (параметр `box`);
- `return` — передача данных назад.

**Остальное решается на месте.** Слайсы, строки и составные значения сами по себе ничего не делают: куда передал — тот контракт и действует. В ссылку — читается, в `box` — потребляется. Однозначного ответа «слайс это чтение или потребление» нет и не нужно.

**Пользовательские функции** список не требуют: контракт в сигнатуре — `link` = чтение, `box` = потребление. Видно сразу.

## Мутация разрывает state-bound контракт

```text
let a = 20
link b = a
```

Оба имени связаны с одним текущим состоянием данных. Связь `link b = a` — контракт с конкретным состоянием: `b` имеет право обращаться к текущему состоянию `a`.

Если затем происходит:

```text
mut a = 30
```

создаётся новое состояние. Старый контракт `link b = a₀` больше не существует. `b` не превращается в dangling reference — старая версия состояния просто перестаёт быть допустимой для дальнейшего использования через этот контракт. Использование `b` после `mut a` — ошибка компиляции.

Чтобы снова получить `b`, необходимо явно написать:

```text
link b = a
```

## `link& b = a` — явная долговременная ссылка

Отдельный синтаксис для ссылки, которая привязана не к конкретной версии состояния, а к слоту/месту:

```text
let a = 20
link& b = a

mut a = 30
```

В этом случае `b` остаётся связанной с тем же слотом/местом и после изменения `a` видит новое значение.

Разница:

```text
link b = a
```

— ссылка на конкретное состояние.

```text
link& b = a
```

— явная привязка к слоту/месту.

`link&` не делает ссылку бессмертной: когда слот умирает (например, переменная выходит из области видимости или объект освобождается), ссылка умирает вместе с ним. Если смерть слота доказуема на этапе компиляции, использование после неё — ошибка компиляции. Если слот может исчезнуть только в рантайме (например, элемент удалён из контейнера), компилятор вставляет проверку существования слота; провал проверки — panic, а не UB.

Главная идея:

> Обычная ссылка короткоживущая и привязана к состоянию. Долгоживущая ссылка должна быть выражена отдельным синтаксисом.

## `link* b = a` — ссылка с заморозкой

`link*` — самая сильная гарантия: пока ссылка жива, данные, на которые она указывает, нельзя изменить вообще. Ни через ссылку, ни через оригинал.

```text
let a = 20
link* b = a

mut a = 30    //// ОШИБКА: a заморожена, пока жива link* b
```

Когда `link*` умирает, заморозка снимается. Пока `link*` жива, любая мутация запрещена, поэтому слот не может исчезнуть: проверка статическая, без runtime-цены.

Разница:

```text
link& b = a    // «я хочу видеть изменения слота» — mut a можно, b следует за изменениями
link* b = a    // «данные не изменятся, пока я смотрю» — mut a запрещён
```

`link&` — это утверждение программиста: «в этот момент слот существует и путь валиден». Компилятор не анализирует, что именно лежит в слоте, — он только проверяет существование пути. Если слот исчез, срабатывает runtime-проверка и программа падает с panic. Если слот существует, но содержит не то, что ожидал программист, — это логическая ошибка кода, а не повод для panic.

Зачем нужен `link*`:
- параллельный доступ — несколько потоков читают, никто не мутирует;
- инварианты — данные не изменятся, пока обрабатываются;
- кэширование — значение гарантированно валидно.

Использование мёртвой `link*` — ошибка компиляции: `link*` замораживает данные, поэтому слот не может исчезнуть незаметно.

Контроль привязан к потребителю, а не к данным: пока данных никто не читает — они свободны. Появился потребитель (`link*`) — данные заморожены. Ссылка умерла — контроль выключился.

## Ссылки на элементы

Ссылка может быть создана непосредственно на нужный элемент:

```text
link b = a[0]
```

означает ссылку на соответствующий элемент текущего состояния. Ссылка привязана к пути (база + индекс/поле), а не ко всему объекту.

Если `a` затем изменяется целиком (`mut a = ...`), обычная связь с предыдущим состоянием `a[0]` прекращается. Даже если после изменения в `a[0]` случайно находится такое же значение, это уже новое состояние.

Инвалидация идёт по пути: мутация убивает только те state-bound ссылки, чей путь пересекается с изменённым. `mut a[1]` убивает `link` на `a[1]` и на `a` целиком, но не на `a[0]`; `mut a` убивает все ссылки, производные от `a`. Если необходимо сохранить привязку к слоту/месту, используется долговременная форма ссылки.

`link& b = a[0]` — это логический путь (база + индекс), а не адрес ячейки в буфере. Реаллокация буфера на `link&` не влияет: путь разрешается заново при каждом использовании. Если элемент удалён (например, `pop` или `clear`), runtime-проверка не находит слот и программа падает с panic. Если элемент существует, но по индексу уже лежит другое значение, — это логическая ошибка программиста, а не ошибка языка.

## Ссылки прямые, без цепочек

Ссылка всегда указывает прямо на данные. Ссылку можно создать только от переменной, в которой лежат данные. От другой ссылки — нельзя:

```text
link b = a
link c = b    // запрещено: ссылка от ссылки
```

Хочешь ссылку на данные — пиши прямо на переменную с данными:

```text
link c = a    // правильно
```

Цепочки невозможны в принципе — не потому что компилятор их ловит, а потому что их нельзя написать. Ссылка всегда указывает прямо на данные, и это гарантировано самим языком.

Передача ссылки в функцию — не цепочка: функция получает то же окно в данные и читает их напрямую. Цепочка — это ссылка на переменную, в которой лежит ссылка; такого в языке нет.

## Ссылка не убегает из функции

Функция может принимать ссылку и читать данные. Передача ссылки в другую функцию с `link`-параметром — это не цепочка: передаётся то же окно в данные, а не ссылка на ссылку. Компилятору не нужно анализировать её заново — используется тот же слот или то же состояние.

Запрещён именно побег ссылки:

- вернуть ссылку из функции;
- сохранить её в структуру, список или замыкание;
- использовать её дольше, чем живут данные.

Если данные нужны глубже или дольше — они передаются через `box` (копия или move) либо через индекс/арену, а не через ссылку.

```text
fn.nothing read(link data: Data) { ... }   // читает напрямую; вернуть ссылку нельзя
```

## Ссылки не прячутся

Ссылка не убегает: `link` живёт там, где создана, `link&`/`link*` — пока живы и существует целевой слот. Ссылку не кладут в списки и не хранят в структурах — это не делается.

Если данные нужны кому-то надолго — их не прячут в ссылку, а передают через box (move или копия). Данные либо у тебя, либо переданы другому, либо скопированы. Третьего не дано.

## Move убивает ссылки

При перемещении (когда box решает move) исходная переменная умирает: ответственным за данные становится новое имя. Память при этом не перемещается. Вместе со старым именем умирают все ссылки на него:

```text
let a = big_object
link b = a            // ссылка на a
let c = box(a)    // a: 1 использование → move, a мертва
print(b)              // ошибка: b мертва вместе с a
```

Правило простое: исходная переменная умерла — ссылки на неё мертвы. Это касается и `link&`: move убивает слот, а вместе с ним и ссылку.

## Копия и независимость

`let b = a` — **всегда копия**. Это явное намерение программиста: «мне нужна независимая копия». `a` остаётся жива.

`b` и `a` больше никак не связаны: мутация `a` не влияет на `b`, и наоборот. Копия — единственный способ получить независимое значение.

Копия делается от переменной с данными: `let c = a`, а не через ссылку.

`box` — другое: компилятор решает копия или move по числу **потребляющих** использований. Чтения через ссылки (`link`) не считаются — читать можно сколько угодно раз, это не потребление.

## Выбор механизма — заявка на намерение

Выбор механизма выражает намерение программиста:

- `let b = a` — «мне нужна независимая копия»;
- `link b = a` — «мне нужно прочитать данные»;
- `link& b = a` — «я хочу видеть изменения слота»;
- `box(expr)` — «я использую реальные данные, компилятор решит копия или move».

Контракт операции определяет, что принимать: ссылку (чтение) или box (использование). Если планируется замена объекта, компилятор поймает любое использование после неё.

## Ссылка — это чтение

Через ссылку можно только читать. Изменить или мутировать через ссылку нельзя — это не её функция. Мутация — это `mut` на самой переменной, где лежат данные. Ссылка на это не способна в принципе.

Обычная ссылка (`link`) безопасна по определению: через неё физически нельзя ничего сломать, потому что она только читает. И она умирает при мутации, потому что данные, на которые она смотрела, изменились, — а она читала старое состояние. `link&` переживает мутацию, поэтому проверяет существование слота в рантайме; `link*` усиливает это до заморозки: пока ссылка жива, данные нельзя изменить даже через оригинал.

## Логические ошибки — ответственность кода

Компилятор гарантирует безопасность памяти: мёртвая ссылка не может быть использована. Если смерть доказуема, это ошибка компиляции; для `link&` с исчезнувшим в рантайме слотом — panic. Логические ошибки компилятор не решает:

```text
let a = 10
link& b = a

mut a = new_object
```

С памятью всё в порядке: `b` жива, слот жив, `b` видит новое значение. Но если `b` ожидала данные старого объекта — это семантическая ошибка кода, а не языка. Если же слот перестал существовать (например, элемент удалён из контейнера), срабатывает runtime-проверка `link&` — panic.
