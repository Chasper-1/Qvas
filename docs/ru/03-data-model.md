# Модель данных

## Механизмы работы с данными

| Механизм | Значение | Что происходит |
|---|---|---|
| `let b = a` | копия | создать независимое значение, `a` жива |
| `link b = a` | ссылка | чтение, `a` жива, умирает при `mut a` |
| `link& b = a` | ссылка на слот | чтение, привязана к слоту/месту, переживает `mut a`; существование слота проверяется в рантайме, провал → panic |
| `link* b = a` | ссылка с заморозкой | чтение, привязана к слоту/месту, `mut a` запрещён, пока ссылка жива; проверка статическая |
| `box(expr)` | реальные данные | компилятор выбирает копия или move |

Контракт операции определяет, что принимает операция: ссылку (чтение) или box (использование). Все операции проверяются компилятором. Использование мёртвой ссылки — ошибка: если смерть доказуема, ошибка компиляции; для `link&` с исчезнувшим в рантайме слотом — panic.


## Нет состояния по умолчанию

Каждое взаимодействие с данными — либо чтение, либо использование. Нет «по умолчанию».

```text
let b = a
```
Создаёт копию. `b` — независимое значение, `a` жива.

```text
link b = a
```
Создаёт ссылку. `b` читает данные, `a` жива.

```text
let sum = box(a + b)
```
Использует реальные данные.


### Чтение — это не потребление

Чтение реализуется через ссылку (`link`, `link&` или `link*`), ничего не изменяет и не потребляет данные. Читать можно сколько угодно раз.

Потребление — это передача данных через box. Компилятор решает: копия или move, по числу потребляющих использований (правило выше).


## Контракты операций

Контракт у операции, а не у значения. Каждая операция заранее объявляет, читает она или потребляет. Без угадывания — гарантия написана.

**Читают (принимают ссылку, на вызове ничего писать не надо):**

- `print`, вывод;
- длина, `isEmpty`, `contains` и прочие проверки;
- сравнения (`==`, `!=`, `<`, `>`, `<=`, `>=`);
- условия (`if cond`);
- чтение по индексу (`a[0]`);
- итерация (`for item in list` — читает список, `item` — ссылка).

**Потребляют (требуют `box`):**

- арифметика (`a + b`, `a * b` — создают новое значение из данных);
- конкатенация строк;
- `push` в список, вставка, хранение в структуру;
- передача в потребляющее вычисление или действие (параметр `box`);
- `return` — передача данных назад.

**Остальное решается на месте.** Слайсы, строки и составные значения сами по себе ничего не делают: куда передал — тот контракт и действует. В ссылку — читается, в `box` — потребляется. Однозначного ответа «слайс это чтение или потребление» нет.

**Пользовательские вычисления и действия** не требуют списка: контракт в сигнатуре — `link` = чтение, `box` = потребление. Видно сразу.


# Ссылки

Есть два возможных способа использовать ссылку, различие исключительно в том, потребляешь ссылку или нет

```text
let a = 20
link b = a
```
Это классический способ создания ссылки.

```text
ignore!(std.print(b))
```
Это просто использование, ничего не происходит кроме чтения.

```text
ignore!(std.print(&b))
```
Вот это означает, единичное использование после которого ссылка умирает. Такой механизм нужен для ссылок link*, о чём далее.


## Мутация разрывает state-bound контракт

```text
let a = 20
link b = a
```

Оба имени связаны с одним текущим состоянием данных. Связь `link b = a` — контракт с конкретным состоянием: `b` имеет право обращаться к текущему состоянию `a`.

Если затем происходит:

```text
mut a = 30
```
Создаётся новое состояние. Старый контракт `link b = a₀` больше не существует. Использование `b` после `mut a` — ошибка компиляции.

Чтобы снова получить `b`, необходимо явно написать:

```text
link b = a
```


## `link& b = a` — явная долговременная ссылка

Отдельный синтаксис для ссылки, которая привязана не к конкретной версии состояния, а к слоту/месту:

```text
let a = 20
link& b = a

mut a = 30
```
В этом случае `b` остаётся связанной с тем же слотом/местом и после изменения `a` видит новое значение.

Разница:

```text
link b = a
```
Ссылка на конкретное состояние.

```text
link& b = a
```
Явная привязка к слоту/месту.

`link&` не делает ссылку бессмертной: когда слот умирает, ссылка умирает вместе с ним.


## `link* b = a` — ссылка с заморозкой

`link*` — самая сильная гарантия: пока ссылка жива, данные, на которые она указывает, нельзя изменить вообще. Ни через ссылку, ни через оригинал.

```text
let a = 20
link* b = a

mut a = 30    //// ОШИБКА: a заморожена, пока жива link* b
```
Когда `link*` умирает, заморозка снимается. Пока `link*` жива, любая мутация запрещена, поэтому слот не может исчезнуть.

Где нужен `link*`:
- параллельный доступ — несколько потоков читают, никто не мутирует;
- инварианты — данные не изменятся, пока обрабатываются;
- кэширование — значение гарантированно валидно.

Использование мёртвой `link*` — ошибка компиляции: `link*` замораживает данные, поэтому слот не может исчезнуть незаметно.


## Ссылки на элементы

Ссылка может быть создана непосредственно на нужный элемент:

```text
link b = a[0]
```
Означает ссылку на соответствующий элемент текущего состояния. Ссылка привязана к пути (база + индекс/поле), а не ко всему объекту.

Инвалидация идёт по пути: мутация убивает только те state-bound ссылки, чей путь пересекается с изменённым. `mut a[1]` убивает `link` на `a[1]` и на `a` целиком, но не на `a[0]`; `mut a` убивает все ссылки, производные от `a`.


## Ссылки прямые, без цепочек

Ссылка всегда указывает прямо на данные. Ссылку можно создать только от данных. От другой ссылки — нельзя:

```text
let a = 10
link b = a
link c = b    // запрещено: ссылка от ссылки
```
Хочешь ссылку на данные — пиши прямо на переменную с данными:

```text
link c = a    // правильно
```

Передача ссылки в вычисление `fn` или действие `sub` — не цепочка: получатель получает то же окно в данные и читает их напрямую. Цепочка — это ссылка на другую ссылку; такого в языке нет.


## Ссылка не убегает из вычисления или действия

Вычисление `fn` или действие `sub` может принимать ссылку и читать данные.

Запрещён побег ссылки:

- вернуть ссылку из вычисления или действия;
- сохранить её в структуру, список или замыкание;
- использовать её дольше, чем живут данные.

Если данные нужны глубже или дольше — они передаются через `box` (копия или move) либо через индекс/арену, а не через ссылку.

```text
sub read(link data: T) { ... }   // читает напрямую; вернуть ссылку нельзя
```


# Box

## Move убивает ссылки

При перемещении `box всегда move, даже при копиях дополнительных` исходная переменная умирает: ответственным за данные становится новое имя. Память при этом не перемещается. Вместе со старым именем умирают все ссылки на него:

```text
let a = big_object
link b = a            // ссылка на a
let c = box(a)    // a: 1 использование → move, a мертва
print(b)              // ошибка: b мертва вместе с a
```

Правило для `box`:

- данные используются один раз → move: данные не копируются, старое имя умирает, память остаётся на месте;
- данные используются 2+ раза → копии: все использования, кроме максимум одного, становятся копиями. Move может быть назначен на фактически последнее использование, но не гарантирован; двух move не бывает.

Считаются только **потребляющие** использования (`box`). Чтения через ссылки (`link`) не считаются — читать можно сколько угодно раз, это не потребление.
