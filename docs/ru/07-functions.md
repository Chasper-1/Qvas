# Вычисления и действия

## Две сущности

```text
fn name(params) -> type { ... }
sub name(params) { ... }
```

`fn` — вычисление: всегда отдаёт ответ, ответ обязан быть потреблён. `sub` — действие: отдаёт чек. Чек — информация о том, куда ушли данные.

## Контракт

Параметры объявляют, читают они или потребляют. Видно в сигнатуре:

- читающий параметр — `link` (ссылка);
- потребляющий параметр — `box` (компилятор решает копия или move по числу использований у вызывающего).

```text
fn read(link data: Data) -> i32 { ... }  // вычисление: читает и отдаёт ответ
sub print_data(link data: Data) { ... }  // действие: читает, отдаёт чек
sub consume(box data: Data) { ... }      // действие: потребляет, отдаёт чек
```

На вызове контракт соблюдается явно:

```text
let n = read(a)                 // параметр link — передаётся ссылка, box не нужен
ignore!(print_data(a))          // действие: чек не нужен — не берём
ignore!(consume(box(a)))        // параметр box — на вызове пишется box
```

Сигнатура показывает, что писать на вызове: потребляющий параметр требует `box` в месте вызова.

Голых параметров не бывает: каждый параметр обязан быть помечен `link` (чтение) или `box` (потребление). Если параметров несколько — на вызове один `box`: `sum(box(x, y))`.

Параметр `link` — чтение: вычисление или действие получает окно в данные. Передача ссылки дальше с `link`-параметром — не цепочка; запрещён только побег (возврат, хранение, использование дольше жизни данных). Нужно передать данные глубже или дольше — через `box` или индекс/арену.

## Вычисление

`fn` всегда отдаёт ответ. Ответ обязан быть потреблён: связан, использован, передан или возвращён. Голый вызов `fn` — ошибка.

```text
fn sum(box a: i32, box b: i32) -> i32 { a + b }

let r = sum(box(3, 5))      // ответ потреблён
```

Возврат — это передача данных назад, отдельный механизм не нужен:

```text
fn make() -> Data {
    let d = ...
    d
}
```

Мутация данных в вычислении:

```text
fn process(box data: Data) -> Data {
    mut data.field = new_value
    data
}
```

Данные пришли (потребление), поменялись через `mut`, вернулись (return = передача). Ответ всё равно обязателен: если ответа нет — это не `fn`, а `sub`.

## Действие

`sub` работает с миром: пишет, отправляет, рисует, вызывает syscall. Данные уходят в память — мир это память. Результат — чек: что записалось, куда, сколько, что отправилось.

```text
sub print(link s: str) -> () or IoError
sub open(link path: str) -> FileId or IoError                     // FileId — куда
sub read_into(link path: str, out buf: [u8]) -> usize or IoError  // usize — сколько
```

Чек — не значение для вычислений, а информация. Нужен — свяжи или разбери. Не нужен — не бери: данные уже размещены, в этом и была работа. Для `print` чек — ошибка вывода (`IoError`); когда вывод не важен, чек не берут: `ignore!(print(x))`.

- `ignore!` — явно не брать чек, видно в коде;
- `switch` / `match` — разобрать на месте.

```text
sub copy(link from: str, link to: str) -> () or FileError {
    let data = read_file(from)
    switch data {
        FileError::NotFound => ignore!(print("нет файла")),
        else => ignore!(write_file(to, data)),
    }
}
```

Если действие может не сработать, оно возвращает `or E`. Ошибка разбирается на вызове, как у `fn`. Проброса нет.

`sub` без `or E` не может не сработать: ошибки нет, вызов идёт как оператор.

```text
sub push(link list: [T], box value: T) { ... }

mut tokens.push(token)      // падать нечему
let top = mut stack.pop()   // pop меняет список и отдаёт снятый элемент
```

`mut` перед вызовом — событие изменения переменной, которой принадлежит метод.

## `out` — запись в чужую память

`link` только читает, `box` забирает. `out` даёт запись и виден на вызове.

```text
sub greet(out buf: [u8]) -> usize { ... }

let buf: [u8] = {}
let n = greet(out(buf))
```

## `main`

Вход объявляется в начале файла:

```text
main() -> Sys
```

Это не тип возврата функции. Это указание, куда уходят данные: `main` отдаёт их в `Sys`. `Sys` — приёмник, не тип.

Для встраиваемых систем приёмник другой: `main() -> Metal`. Имя приёмника даёт платформа, язык его не фиксирует.

`main` — действие, у него нет вызывающего в языке: его запускает платформа и читает то, что ушло в приёмник. Ошибки внутри `main` разбираются на месте, как везде.

Обратной записи `Sys = main()` нет: граница одна, пройти её дважды нельзя.

## Сахар

Удобные формы (`getline!`, `read_into!`) — тонкая надстройка. Правила три:

- раскрытие видно: IDE и документация показывают, во что разворачивается форма;
- тег следует из раскрытия, а не из имени: если внутри действие, вся форма — действие, и из `fn` её звать нельзя;
- раскрытие умещается в голову: «вот действие, вот вычисление».

`getline!` раскрывается в `read_into` плюс срез буфера; тег у него — действие.

## `mut` и move не смешиваются

`mut` меняет значение, move меняет имя, ответственное за данные. Либо одно, либо другое.

## Вычисления как значения

Вычисление можно передать в вычисление — как везде:

```text
fn apply(link f: Fn, box value: i32) -> i32 {
    f(value)
}

let result = apply(my_func, box(42))
```

`sub` значением не является: его нельзя положить в переменную или передать как `Fn`.

## Вызовы

`fn` вызываются из любого `fn` или `sub` без указания вызова в сигнатуре. Вызов — использование готовой логики: одна функция, много вызовов. Неявных входов нет: данные приходят только через параметры по контракту. Логика функции не зависит от логики вызывающего.

`fn` не вызывает `sub`: вычисление не выполняет действий. Вызов идёт только в одну сторону — `sub` вызывает `fn`, но не наоборот. Если внутри вычисления нужно действие — это действие, а не вычисление.

## Возврат

Ответ — данные, передача — move. Ответ не ссылка; одновременно в двух местах его нет.

## Рекурсия

Прямой самовызов — невыполнимый контракт, а не рекурсия: функция требует свой ответ сейчас, а его ещё нет. Рекурсия возможна только через ветвление: ответ имеет тип, полученный от самой функции, запускается другая ветка с иными вычислениями.
