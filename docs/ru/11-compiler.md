# Компилятор

## Бэкенд: Cranelift

Компилятор строится на Cranelift.

## Оптимизации — во фронтенде

Явная модель даёт точный алиасинг, точные времена жизни, нет скрытого состояния → высокоуровневые оптимизации (инлайнинг, устранение копий, escape analysis) делает фронтенд.

Cranelift — кодогенерация (регистры, планирование). Его проходы не отключаем — они бесплатны и дополняют.

## Главная работа: IR

Главная инженерная работа — IR (SSA, с семантикой языка):

```text
AST → IR → оптимизации → Cranelift
```

## Плоский AST (арена)

Один `Vec<Node>`, индексы вместо указателей — быстрее и проще. Как ECS в геймдеве.

Полностью без дерева — только быстрый путь для простого кода; общий путь — арена (анализ ссылок/databox/параллелизм нуждаются в структуре).

## Дальше — фронтенд решает

Inlining и move/copy (databox) — решает фронтенд по числу использований.

## Backend-friendly IR

Изучить, какие паттерны узнаёт оптимизатор Cranelift, и давать ему ровно их.

## Синтаксис

Синтаксис глобально не меняется; возможны микро-доработки для простоты разбора.

## Параллельный анализ

После построения дерево разбирается по ядрам: каждая функция/блок анализируется отдельно, межпроцедурный анализ — сверка контрактов.
