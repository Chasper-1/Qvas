# Параллелизм

## Граф зависимостей

Синтаксис: `parallel { ... }` — блок, в котором пишешь, что делать параллельно. Компилятор строит граф зависимостей и планирует сам.

```text
parallel {
    let x = compute_x()
    let files = load_files()
    let result = process(x, files)
}
```

Граф:

```text
compute_x ── x ──→ process
load_files ──────→ process
```

`compute_x` и `load_files` независимы — выполняются параллельно. `process` начинается только после получения необходимых результатов.

## Односторонние зависимости

Зависимость должна существовать только там, где она действительно нужна.

Если результат `A` нужен `B`, то достаточно:

```text
A
↓
B
```

Это не означает, что `B → A`. Независимые части программы не должны искусственно блокировать друг друга.

## Автоматическое планирование

Компилятор может преобразовать зависимости в граф задач и затем выбрать способ их выполнения:

- последовательно;
- параллельно;
- на отдельных потоках;
- через worker pool;
- через другой лёгкий scheduler.

Главная идея:

> программист описывает семантические зависимости, а не вручную расставляет каждую точку синхронизации для независимых операций.

Низкоуровневые примитивы вроде mutex/atomic/channel при необходимости всё равно могут существовать.

## Параллелизм не равен безопасности памяти

Параллельное выполнение рассматривается как отдельный уровень.

Программа может быть:

- memory-safe, но логически неправильной;
- корректной по зависимостям;
- некорректной из-за неправильной организации параллельных операций.

Безопасность памяти и корректность параллельной логики не обязательно должны быть одной и той же системой правил.

Общие данные в параллельном блоке читаются через ссылки. `link*` замораживает данные на время параллельного чтения — никто не сможет их изменить.

```text
let data = load_data()
link* view = data

parallel {
    process_a(view)
    process_b(view)
}
```
